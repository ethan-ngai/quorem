# 36c: Remote runner composition

Issue #423. The trusted runner requires `QUOREM_SANDBOX_PROVIDER=docker|remote`. Docker uses `QUOREM_DOCKER_SOCKET`, `QUOREM_DOCKER_FENCE_ROOT`, and `QUOREM_DOCKER_NAMESPACE`. Remote requires `QUOREM_CASE_ORIGIN`, `QUOREM_CASE_SECRET`, `QUOREM_CASE_NAMESPACE_ID` (the actual 64-hex namespace sentinel), and `QUOREM_CASE_OWNER_PUBLIC_KEY_FILE` (absolute Ed25519 public PEM). Both use `QUOREM_SANDBOX_CLEANUP_MS`. Optional `QUOREM_CASE_ACCESS_CLIENT_ID` and `QUOREM_CASE_ACCESS_CLIENT_SECRET` are paired, HTTPS-only and distinct from the command ingress and runner credentials. Remote composition invokes the canonical namespace- and key-pinned adapter; an unconfirmed deletion retains the existing teardown failure behavior.

Local validation: runner typecheck and ten Node runtime/remote tests pass, including actual Docker process startup and continuous polling, remote process startup and invalid key rejection, missing/switching owner and ambiguous deletion. The existing workerd attestation fixture returned valid POST/DELETE signatures for its namespace and rejected altered input. The separate executable admission-to-Docker-to-HTTP-verifier promotion test passed on disposable PostgreSQL, including active shutdown.

**Remaining gate:** an admitted job has not yet been run through a separate remote runner process, actual case ingress, independent verifier and promotion in one test. The native attestation fixture signs protocol responses but does not expose a configurable executing case service. Hosted namespace provisioning, case service execution and provider lifecycle remain unverified; do not treat this slice as full 36c acceptance.
