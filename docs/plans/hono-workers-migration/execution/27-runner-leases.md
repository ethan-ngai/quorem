# 27 — runner queue

The private PostgreSQL owner claims only compatible runtimes and lossless/checkpoint capabilities. Reclamation requires the exact expired attempt and sandbox scope after the runner awaits teardown; notification IDs do not authorize a claim. Lease, checkpoint, yield and terminal writes recheck the pair and database wall clock after locking. Existing guest metering and match reconciliation remain transaction-owned. Runner terminal and yield helpers await exact-scope teardown before sending commands.

The private HTTP command transport binds each credential to a configured scope and capability profile. HTTPS is required except for loopback fixtures; redirects fail closed and failed mutations are classified as unknown and are not automatically replayed. Request cancellation reaches the owning database scope. It streams checkpoint replay and sends completion fields in 64 KiB chunks. 052 persists attempt-fenced staging and terminal receipts, normalizes public and private result fields, protects terminal rows, and follows existing result retention. A receipt makes an explicit retry after a lost acknowledgement idempotent even after requeue. Public expected values and case status are derived from admitted run cases or sample fixtures; runner-supplied expected bytes are not published.
