# 11 Auth composition (#359)

Better Auth receives configuration, the pinned official per-operation Drizzle adapter, semantic auth repositories and a durable mail gateway. Core owns each connection's lifetime; SDK operations use their own scope, with a real transaction for an SDK transaction callback. Auth profile, assurance, social proof and persistent rate-limit queries use qualified `quorem_auth` tables. Better Auth's per-instance memory limiter is replaced by atomic PostgreSQL limits so request-local Worker factories cannot reset it. Unsafe profile revisions fail closed.

Node uses explicit `createNodeRuntime(env)` startup: importing the factory, server or CLI modules does not read environment or create a pool. The Node listener retains the existing Better Auth Node handler and authenticated internal session endpoint; that listener must remain private. The Worker uses the native Hono request/response mount, preserves Set-Cookie headers and exposes no `/internal/session` route. Its private `AuthRepository.sessionAuthority` is available for a same-process or service-binding adapter. Node and Worker wire the mail repository and intent service to the actual transport, without routing the service-backed sender into itself. Selected mail requires `AUTH_MAIL_INTENT_KEY`: exactly 32 bytes encoded as 64 hexadecimal characters; the key is neither included in public configuration nor logged. The Worker accepts only the Cloudflare HTTPS mail adapter. No Worker profile upload handler is mounted.

The backend-only `ConnectionScope.withDatabase` shares the existing connection lifetime, abort and release owner. It guards escaped handles and lazy builders and disallows raw client/session access, concurrent scope operations and detached queries. This is a lifecycle aid for trusted adapters, not a general sandbox. A real pinned Better Auth SDK transaction with a deferred PostgreSQL trigger was terminated during COMMIT; the result was classified unknown_commit and its callback ran once without replay.

## Validation

PostgreSQL 17, Better Auth/passkey 1.7.7, Drizzle 0.45.4, Wrangler 4.156.0/workerd 1.20261023.1. All auth sources and tests typechecked without exclusions; the Node suite passed 104 tests with one Mailpit-dependent test skipped. Node 24 directly imported all CLI/server modules without configuration or startup, and an explicit listener start/stop test passed. Node migration and seed CLIs ran against the disposable database. All 22 durable-mail PostgreSQL tests passed separately. The optional local Mailpit HTTP API responded, but its SMTP port accepted TCP without a greeting; the Mailpit-dependent integration could not be verified. No real mail was sent.

Native workerd with a disposable PostgreSQL 17 database and direct local Hyperdrive binding passed Worker/Node password and session interoperability, verified-email enforcement, live assurance and revocation, profile-image policy, unsafe revision rejection, persistent rate limits and public `/internal` 404. A local Ed25519 virtual authenticator performed real registration and signed assertions: verified assertions set strong assurance; unverified ones did not. Challenge replay, forged signatures, repeated/out-of-range counters and assertions after passkey deletion failed; the uint32 maximum succeeded once. A fixture-only transport verified registration proof, encrypted intents, Better Auth reset mail and absence of idle transactions during delivery. Multiple Set-Cookie preservation passed in the native Hono test. Core passed 12 PostgreSQL tests and workerd checks, including escaped/lazy handle and detached-query cleanup. Social proof mutations and session authority are checked after lock delays against PostgreSQL wall-clock time; rate windows start after the bucket lock is acquired.

Reproduce only with isolated fixtures; the native scripts clear rate-limit rows in the named test database. Start PostgreSQL on 55438 with database `quorem_hono_auth_native_test`; set `AUTH_TEST_DATABASE_URL` to that disposable database and `AUTH_MAIL_INTENT_KEY` to a fixture 64-hex key for `vp -C apps/auth test --run`. Run the Node-only mail suite separately with `QUOREM_MAIL_TEST_DATABASE_URL` targeting disposable `quorem_hono_mail_test` on 55440 and `vp -C apps/auth run test:mail`. Start local Wrangler using `apps/auth/wrangler.native-test.jsonc` on port 58738 and `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_DB` targeting the 55438 database; then run `vp -C apps/auth exec node src/native-worker-check.mjs`, `src/native-passkey-check.mjs` and `src/native-mail-check.mjs`. The Worker fixture exposes seed, mailbox and authority routes solely for tests and must never be deployed.

## Remaining gates

The root lockfile/importers are synchronized. Physical/browser WebAuthn, concurrent passkey assertions, production social/Cognito round trips, hosted provider availability, actual mail delivery, Hyperdrive pooling, and production private authority wiring remain unverified. Better Auth warned the local fixture has no trusted client IP and falls back to a shared per-path bucket; validate trusted proxy/IP configuration before deployment. Key provisioning, rotation and expired-intent retention remain operator/deployment work. Worker profile uploads remain disabled until packet 12 supplies shared mutation admission and an image processor.

`createProfileHandler` keeps mutation windows and the processing counter in its closure. Node constructs it once; per-request Worker construction would reset those controls. `ProfileMutationBudget` is only a proposed interface. Packet 12 must implement atomic shared per-user windows and bounded global processing leases, preserve the 10-per-minute, four-in-flight and bounded-subject policies, release idempotently and fail closed. Lease expiry must exceed operation lifetime, and stalled work must be canceled before reclaiming capacity.
