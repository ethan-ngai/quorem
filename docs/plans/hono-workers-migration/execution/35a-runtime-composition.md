# 35a runtime composition

In progress; not ready for deployment. `apps/api/src/runtime/node.ts` exports `startNodeRuntime(env)` and owns Node HTTP, PostgreSQL fanout, notification listener, deadline and execution recovery. `apps/api/src/runtime/worker.ts` exports default `fetch` and `scheduled`, plus Durable Object classes `BrowserSockets`, `DeadlineCoordinator` and `ExecutionRecovery`. Auth remains the canonical `@quorem/auth/node` and `@quorem/auth/worker` composition; profile media uses the existing configured Node/R2 providers. The API package declares `@quorem/auth: workspace:*`; its lock entry is integrated.

Node requires `DATABASE_URL`, `AUTH_DATABASE_URL`, `QUOREM_DATABASE_LISTEN_URL`, `QUOREM_ALLOWED_ORIGINS`, `MATCH_INVITE_KEY` (32-byte lowercase hex), and `EXECUTION_WAKE_PROVIDER` (`sqs` with `SQS_QUEUE_URL`, or `cloudflare-rest` with `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_QUEUE_ID`, `CLOUDFLARE_QUEUE_TOKEN`). `HOST` defaults to loopback, `PORT` to 8080; local mode requires loopback. `SQS_LOCAL_ENDPOINT` is permitted only in local mode with a loopback HTTP origin; `QUOREM_DATABASE_MAX_CONNS`, `HTTP_MAX_REQUESTS`, `SOCKET_HEARTBEAT_MS` (1000–120000; default 15000), `DEADLINE_SHARDS`, `GUEST_ADMISSION`, `GUEST_EXECUTION`, and `IDENTITY_MODE` are bounded/explicit settings. Local identity is only selectable with `APP_ENV=local`. Auth settings are owned by `apps/auth/src/config.ts`; managed sessions use Better Auth's real JWKS and live session authority.

Worker requires Hyperdrive `DB`, queue producer `EXECUTION_QUEUE` when `EXECUTION_WAKE_PROVIDER=cloudflare-binding`, and DO namespaces `SOCKETS`, `DEADLINES`, `EXECUTION_RECOVERY`. The `queue` entry point consumes wake messages using `EXECUTION_DRAIN_URL` (HTTPS `/internal/drain`, or explicit local loopback HTTP) and `EXECUTION_DRAIN_SECRET` (at least 32 bytes and distinct from all private runner/verifier credentials). `EXECUTION_DRAIN_ACCESS_MODE` must explicitly select `none` or `cloudflare-access`; the latter requires paired `EXECUTION_DRAIN_ACCESS_CLIENT_ID` and `EXECUTION_DRAIN_ACCESS_CLIENT_SECRET` and HTTPS. It publishes any required delayed continuation before acknowledgment and retries failures. `cloudflare-rest` wake uses the same three Cloudflare queue strings as Node. Worker uses `ALLOWED_ORIGINS`, `MATCH_INVITE_KEY`, the same optional flags and auth settings. `BrowserSockets` uses a stable Durable Object per stream and aggregate. Invitation and membership scope comes from the verified current grant before routing, then the object rechecks it; object names never include invitation tokens. DO attachments retain only opaque server-created grant IDs. No credentials are included in notices or attachments.

Both runtimes mount canonical catalog, authoring, workspace, submission/admission/results, match/invite, interview lifecycle/question/document/presence/monitoring/execution, guest and Better Auth routes. The private runner endpoints require `RUNNER_PEERS` JSON containing scoped credentials and resumability; verifier source uses `VERIFICATION_SOURCE_CREDENTIAL`, verifier service uses distinct `VERIFICATION_SERVICE_CREDENTIAL` and `VERIFICATION_SERVICE_ORIGIN`, and `VERIFICATION_PUBLIC_KEY` is base64 SPKI Ed25519. All peer and verifier credentials must be distinct. The API contains no signing private key. The HTTP concurrency permit remains held through response-body EOF, cancellation or request abort; sockets use the independent PostgreSQL lease quota.
