# 29: runner orchestration

Issue #402. Partial implementation; full packet remains open pending normalized bounded input, production composition, recovery and failure tests.

The private control API returns database-clock runnable deadlines, queue counts, and empty confirmation under the admission advisory lock. The Node runner claims through 27, performs live lease checks at one-second intervals and renews every 15 seconds. Failed checks or cancellation abort execution; no completion or yield occurs before confirmed sandbox teardown. Failure detection is bounded by the poll interval plus private command timeout, not instantaneous. Engine yields only at a persisted case boundary; the existing lease owner handles release.

Bounded HTTP drains require a 32-byte private credential and return 202 for incomplete or overlapping work. A wake consumer must persist continuation before acknowledging incomplete work. The provided consumer contract preserves that ordering; provider-specific durable delivery and production entrypoint wiring remain open. HTTP mode performs control polling only during an active drain. Native Worker HTTP commands do not require a Node PostgreSQL notification listener or give database credentials to the runner.

Local evidence: real PostgreSQL plus private HTTP handler, 18 Hono admission, Node runner, Python Docker, 27 promotion and 19b authorized Hono result stream pass end-to-end, including nonowner rejection. A looping admitted Docker case is cancelled through Hono, confirmed removed, then reclaimed and marked cancelled after lease expiry. Real Docker checkpoint-yield/resume, five language harnesses, a 1 MiB Python argument and rejected PostgreSQL server-file access pass. Drain unit tests exercise pre-admission grace, bounded incomplete response, overlapping HTTP wakes, lease loss and continuation-before-ack. Native workerd with disposable PostgreSQL exercises queue control commands. These tests do not establish hosted latency, capacity, provider delivery, cancellation under a real network partition, complete SQL role isolation or large legacy case behavior.

Migrations 053–055 establish immutable content-addressed fixture and job input references, active interview binding, and retention guards. The private manifest and bounded page API binds reads to the live job, attempt and scope; the Node side checks hashes while streaming to disk and sandbox. The old whole-spec loader and successful promotion reject manifest jobs until independent streaming result verification is implemented. The earlier end-to-end test exercised the pre-manifest path; it does not establish the normalized path. Legacy normalization, old-writer drain, independent large-case comparison and verified match evidence, retention-safe unreferenced blob collection, and production composition remain activation gates.

Fixture source identity uses SHA-256 of exact persisted lossless bytes when present; snapshots without lossless bytes use PostgreSQL JSONB text. Versions without lossless bytes use a domain-separated hash of eight ordered leaves: metadata, languages, tags, examples, hidden cases, Odyssey stage metadata, stage examples, and stage cases. Row leaves hash fixed-width per-column hashes, with 00 for null and 01 plus PostgreSQL UTF-8 text for nonnull values; list leaves hash ordered row hashes. Shared metadata/case encoders and blob insertion validate identical replay and reject conflicting bytes. Disposable PostgreSQL tests cover source bytes including whitespace, unicode, escaped NUL and numeric lexemes, canonical numeric metadata, and a 4 MiB statement. The operator backfill and an end-to-end normalized execution are not yet validated.

The normalized verifier path now freezes each staged frame, fetches its immutable case through fenced pages, and has a trusted Node service run the canonical comparison and sign an Ed25519 receipt. The API verifies the receipt outside its commit transaction and rechecks the attempt, cancellation, manifest binding, frame hash and output chunk hashes under lock. Promotion derives score and hidden statuses from verified evidence, and requires complete manifest coverage. Public result fields are copied from verified frames; private frames remain server-owned. The verifier holds one case/frame in Node memory after digest-checked disk spooling. Provider credentials and its signing key never enter a sandbox.

Local disposable PostgreSQL tests exercised signed comparison, forged-result rejection, cancellation, idempotent receipt/promotion, and SQL catalog parity for 057. A native workerd test used PostgreSQL and a separate local Node verifier for real Ed25519 receipts, outage and tamper rejection, checkpoint replay and promotion. Real Docker tests passed across all five language harnesses, compiled reuse, Python NUL/Odyssey, timeout, checkpoint yield/resume, forged teardown proof and SQL server-file denial. These are component tests: normalized admission → Docker → verifier → authorized result streaming has not yet been executed. The 058 suite digest migration, production service routing/secrets, normalized legacy backfill/drain, and full recovery/capacity tests remain open.
