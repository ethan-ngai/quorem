# 29: runner orchestration

Issue #402. Partial implementation; full packet remains open pending normalized bounded input, production composition, recovery and failure tests.

The private control API returns database-clock runnable deadlines, queue counts, and empty confirmation under the admission advisory lock. The Node runner claims through 27, performs live lease checks at one-second intervals and renews every 15 seconds. Failed checks or cancellation abort execution; no completion or yield occurs before confirmed sandbox teardown. Failure detection is bounded by the poll interval plus private command timeout, not instantaneous. Engine yields only at a persisted case boundary; the existing lease owner handles release.

Bounded HTTP drains require a 32-byte private credential and return 202 for incomplete or overlapping work. A wake consumer must persist continuation before acknowledging incomplete work. The provided consumer contract preserves that ordering; provider-specific durable delivery and production entrypoint wiring remain open. HTTP mode performs control polling only during an active drain. Native Worker HTTP commands do not require a Node PostgreSQL notification listener or give database credentials to the runner.

Local evidence: real PostgreSQL plus private HTTP handler, 18 Hono admission, Node runner, Python Docker, 27 promotion and 19b authorized Hono result stream pass end-to-end, including nonowner rejection. Real Docker checkpoint-yield/resume, five language harnesses, a 1 MiB Python argument and rejected PostgreSQL server-file access pass. Drain unit tests exercise pre-admission grace, bounded incomplete response, overlapping HTTP wakes, lease loss and continuation-before-ack. Native workerd with disposable PostgreSQL exercises queue control commands. These tests do not establish hosted latency, capacity, provider delivery, cancellation under real network partition, SQL role isolation or large legacy case behavior.

The current 18 admission and 27 load paths still materialize complete fixture/case payloads in a Worker. The Go authoring request bound is 2 MiB and custom cases are bounded at 2 MiB, but neither establishes a bound for legacy/imported fixtures or the aggregate lossless sidecars. Migration 053 is planned to normalize content-addressed immutable metadata and case references with concrete fixture foreign keys, paged private fetches and job/attempt/scope/hash fencing. Legacy normalization, old-writer drain, large-case incremental validation/comparison, and retention-safe unreferenced blob collection are activation gates. No 053 schema or backfill is claimed complete here.
