# 35e: Staged deployment checkpoint

Issue #427. `.github/workflows/hono-stage-deploy.yaml` is manual with `plan` default; it checks the exact workflow SHA on `feat/hono-migration`, runs local runtime/container and Terraform validation, and plans the two independently locked staged state keys. The plan path restricts the database name, Worker names, distinct staged origins, disabled queue, and immutable Cloudflare registry image digests. Terraform/provider output is withheld; only strictly parsed resource actions and counts are returned. No binary plan or secret artifact is saved. The `hono-stage-plan` environment supplies account, R2 state credentials and Terraform inputs; the state store must already be encrypted and access-restricted. Plan reads real cloud state and needs its own authorization; it has not been invoked here.

The protected `hono-stage` action intentionally fails before cloud access. It is not an implemented deployment: the signed namespace helper and hosted accepted execution check are pending. Before enabling it, validate real Worker auth with `hono-stage-preflight`, provision isolated Hyperdrive and private services with a non-authorizing namespace, verify the actual signed namespace proof, derive and pin the canonical runner scope, deploy Worker secrets and route, prove Access and disabled alternate origins, verify real admission through hosted runner/verifier/case teardown, and only then attach the bounded queue consumer. A local fixture or unsigned discovery response cannot satisfy those gates. The workflow requires an explicit namespace input. Terraform creates an immutable state pin for the first nonzero namespace; later changes, reset to zero, destroy and rollback to a different namespace fail under the ordinary backend lock. The pin only fences state: the first nonzero value still requires signed namespace proof. Record release SHA, immutable image digests, schema/backfill and old-writer/judge drain evidence; prohibit rollback when migrations are incompatible.

Local validation: `node --test scripts/hono-stage-deploy.test.mjs` passes guard, ordering, disabled stage and output-redaction fixtures; `vp check --no-fmt scripts/hono-stage-deploy.mjs scripts/hono-stage-deploy.test.mjs` passes; workflow YAML parses. No workflow was invoked and no real Terraform plan, apply, migration or deploy was performed. Hosted TLS, private ingress, secrets, storage and isolation remain unverified.

Namespace pin verification: local Terraform data-only state tested zero→A, A→A, A→B, A→zero, destroy and rollback; only zero→A and A→A succeeded. No Cloudflare provider or cloud state was used.

`scripts/hono-stage-deploy-acceptance.mjs` supplies the actual stage admission → protected drain → accepted result probe for a separately seeded authenticated workspace and known source. Its unit fixtures do not represent a hosted run; its successful hosted invocation, Access-negative checks and safe fixture lifecycle remain required before queue attachment.

`scripts/hono-stage-deploy-images.mjs` builds the runner/verifier and case images from the checked-out revision, pushes their SHA tags and reads back matching Docker repository digests; it passes only registry credentials to Wrangler and does not log subprocess output. It is not yet wired to the stage action or exercised against a registry.
