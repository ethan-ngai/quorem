# 35d Staged private services

Issue #424. The staged service Worker owns separate Node runner, Node verifier and CaseSandbox containers on distinct Custom Domains. Workers.dev and previews are disabled. Custom Domains support same-zone Worker fetches; ordinary Worker routes do not provide that path. [Cloudflare routes](https://developers.cloudflare.com/workers/configuration/routing/routes/) Terraform state contains sensitive Worker bindings and requires encrypted, restricted storage.

The HTTPS drain, verifier, case and recovery-control endpoints require distinct purpose-scoped application bearers. Case execution and teardown additionally bind the actual pinned namespace, derived scope, attempt and fresh nonce to signed proofs. The ingress strips incoming Access credential headers and does not forward the case bearer to the case container. Wrong hosts, paths, methods, credentials and namespace bindings fail closed. Stage-only namespace and lifecycle diagnostics require `case_diagnostics=true`; `deploy/hono/services/probe.mjs` verifies the Ed25519 namespace proof. A zero bootstrap sentinel cannot authorize execution or teardown; pin the verified namespace before enabling delivery.

The remote runner receives its command and case credentials, namespace and public key; it has no Docker socket or verifier signing key. The verifier receives its own source/service credentials and signing key. The case signing key remains in the Worker. Contestant containers receive no service credentials or internet access. Configure API verifier and queue drain transports with `VERIFICATION_ACCESS_MODE=none` and `EXECUTION_DRAIN_ACCESS_MODE=none`; bearer authentication and signed proofs remain required.

The bounded signed lifecycle observation reports active/running state, ordinal and a non-authorizing token digest; full-attempt DELETE remains the teardown authority. Local Node and workerd tests exercise scoped ingress, signed proofs and teardown fencing. Hosted routing, remote execution, cancellation, container isolation, teardown and capacity remain unverified activation gates.
