# Match lifecycle

Packet 20b supplies unmounted create, current/read, settings, ready, start, leave and forfeit routes and their PostgreSQL owner. It reuses `reconcileMatch`, exported transaction-bound `finishMatch`/`matchEvent`, and exported catalog `readCandidates`. Start pins the current sealed, owner-visible problem and version before creating participant workspaces; SQL problems select PostgreSQL. Guest hosting checks the live entitlement on creation, settings and start. Invitation replay uses the existing Go-compatible AES-GCM envelope and an injected 32-byte key.

Command lock order is the existing owner/route/key advisory lock, owner row `FOR NO KEY UPDATE`, then match row `FOR UPDATE`; reconciliation and outbox writes run under that aggregate lock. Create, ready and start prearm the deadline coordinator and consume the receipt in the activation transaction. Guests are revalidated under the match lock, including replay. The constructor is `matchLifecycle(run, { inviteKey, receipts, coordinator, shards, guestCreation })`; `matchLifecycleRoutes({ lifecycle, identify })` is intentionally unmounted. Transaction-bound `lockMatchOwner`, `lockMatch`, `requireMatchMember` and `matchSnapshot` are available to the join owner. The scoped idempotency command remains private; packet 21 must extract it into this shared owner when its join/rotation replay contract is wired.
