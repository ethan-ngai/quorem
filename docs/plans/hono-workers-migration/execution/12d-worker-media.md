# 12d: Worker profile media

Worker profile routes are enabled only with `PROFILE_MEDIA_ENABLED=true`, a native `PROFILE_BUCKET` R2 binding, `PROFILE_IMAGE_SERVICE_URL`, and a shared `PROFILE_IMAGE_SERVICE_TOKEN` of at least 32 characters. Missing or invalid selected capabilities fail composition. Remote URLs require HTTPS and an exact origin without credentials, path, query, or fragment; plain HTTP is accepted only for loopback with `APP_ENV=local`. Redirects are never followed. R2 operations use bounded object reads and private keys; profile lookup, session checks, compare-and-set, object cleanup, and response cache policy remain in the shared handler.

The Node image service is started with `node apps/auth/src/image-service-main.ts`, `IMAGE_SERVICE_TOKEN`, optional `IMAGE_SERVICE_HOST`/`IMAGE_SERVICE_PORT`, and for non-loopback hosts `IMAGE_SERVICE_TLS_KEY_FILE`/`IMAGE_SERVICE_TLS_CERT_FILE`. The HTTP listener rejects non-loopback sockets; production uses private network placement plus authenticated HTTPS. The service bounds input to 5 MiB, accepts at most four concurrent children and 16 connections, and sends an execution-terminated marker only after its child has exited. A credential-free supervisor owns each child and kills it on IPC disconnect from the service; the child receives an empty environment, performs the existing Sharp format/static-page, 16 MP, orientation, 512-cover/no-enlargement, WebP 85 and metadata-stripping policy, and has a 10-second termination deadline. Abort or deadline asks the supervisor to send SIGKILL and awaits child and supervisor close. SIGTERM stops accepting requests and closes active connections, which initiates the same drain. Node profile uploads use the same isolated processor and policy.

A lost service response cannot establish child termination. The Worker therefore retains its fenced database lease on transport failure or an unproven response; there is no TTL reclamation. Image-service process loss, worker loss, and release failures may strand capacity. Safe reconciliation of such leases still needs a durable executor-termination proof and fencing; local tests do not establish recovery or liveness. Hosting resource limits, network isolation, and provider deployment remain packets 35/36. No cloud deployment or credentials were used.

## Evidence

- Native Wrangler/workerd 1.20261023.1, disposable PostgreSQL 17 on port 55450 and local R2: actual isolated Sharp HTTP upload/read/delete, profile GET/PATCH, two concurrent uploads with one stale CAS, format mismatch, revocation and ownership checks passed. An unreachable service returned 503 and retained its lease; run the same script with `--outage` while the service is stopped. Run the fixture with `wrangler dev --local --config apps/auth/wrangler-media-test.jsonc --port 58751`, Hyperdrive pointed to `postgres://postgres:fixture-only@127.0.0.1:55450/quorem_hono_media_test`, start the local service on port 58752 with token `fixture-token-` repeated three times, then `node apps/auth/src/media-native-check.mjs`. The script deletes budget rows only in that fixed disposable database.
- Real child tests cover PNG/JPEG/WebP, animation rejection, malformed bytes, 16 MP boundary, EXIF rotation, crop, metadata stripping, abort/kill and transport uncertainty; a local TLS fixture verified the authenticated HTTPS listener with certificate validation. Twenty-six auth tests, typecheck and scoped lint pass.
- Native workerd WASM probe, `@jsquash/jpeg` 1.6.0: 4000×4000 JPEG decoded to 64,000,000 RGBA bytes in 133 ms local elapsed; an EXIF orientation-6 4000×3999 image decoded as 3999×4000 in 99 ms. Reproduce with `node apps/auth/src/media-wasm-input.mjs`, install the isolated `apps/auth/wasm-probe` package using `vp install -- --ignore-workspace`, run its `wrangler dev --local --port 58750`, then POST `/tmp/quorem-wasm-square.jpg` and `/tmp/quorem-wasm-rotated.jpg` to that port. These are local wall times, not hosted CPU or memory measurements. The probe establishes JPEG decoding and orientation only; full static-frame detection, resize/cover parity, WebP encoding, and the complete pipeline within the [128 MiB Worker limit](https://developers.cloudflare.com/workers/platform/limits/) remain unproven. The [codec documentation](https://github.com/jamsinclair/jSquash/tree/main/packages/jpeg) describes opt-in orientation handling. The established Sharp policy was retained rather than inventing an unverified image pipeline.


Hardening: actual process-tree fixtures stop an active Sharp child and send SIGKILL or SIGTERM to its service; the supervisor kills and reaps the child in both cases. A native workerd request against disposable PostgreSQL also kills the service mid-execution, observes HTTP 503, confirms child termination, and confirms the admission lease remains charged. Run `node apps/auth/src/media-crash-native-check.mjs` with the media Worker running and service port 58752 free. The auth subapp is exercised under parent middleware in workerd; request ID, no-store, and multiple Set-Cookie headers survive. Local tests do not prove survival of a supervisor crash, kernel/host failure, or container teardown; no automatic reclaim is based on this process-tree evidence. The client enforces a 12-second response deadline, cancels rejected bodies, bounds streamed bytes, and rejects redirects; transport timeout remains an uncertain execution outcome.

Root integration review: child termination now requires an explicit supervisor IPC receipt sent after the child close event. Unexpected supervisor exit returns `ImageExecutionUncertain`; the image service withholds its termination header and retains local capacity, and the shared profile handler retains the database lease. A real process fixture SIGSTOPs the Sharp child, kills only its supervisor, observes the still-live child and HTTP 503 without termination proof, then explicitly cleans up the fixture. The focused media/HTTP suites passed 17 tests with one database-dependent skip; auth/API typechecks and full lint passed after rebase.
