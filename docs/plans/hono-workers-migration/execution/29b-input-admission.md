# 29b: normalized input admission

Workspace and interview admission select ordered 053 case hashes from sealed indexes and bind the source, fixture, runtime, counts and channels to the job in the existing transaction. Classic interview submits with no hidden cases use their sample references once. Odyssey selection uses the locked current level and cumulative indexed stages. Custom inputs use the shared case validator against projected schema metadata and store the exact validated case bytes. Admission never selects the legacy fixture or aggregates case bodies into the Worker. The existing 64 KiB source and 2 MiB custom request bounds remain. Metadata selected for custom validation contains only signature, constraint, SQL and unlocked method definitions; prose, descriptions and later methods stay in PostgreSQL. Existing authoring collection limits bound row counts; a 5 MiB serialized-projection guard fails closed on malformed legacy metadata and sits above the existing 2 MiB authoring-body bound. Publication and the legacy normalization operator must validate the same canonical metadata.

The current question epoch must have a sealed 054 interview snapshot mapping; missing mappings or indexes fail closed. Workspace retry rechecks current workspace access, match membership and guest credentials before replay. Interview retry keeps its existing active membership check. Old lossless-capability=false peers fail closed; new submissions intentionally store empty legacy `cases` and do not dual-write old full fixtures.
