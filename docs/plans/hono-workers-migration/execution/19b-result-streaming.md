# Result streaming

The result routes capture a terminal header, authorized membership, sidecar completeness and PostgreSQL row versions before returning a pull-driven JSON stream. Each subsequent read retrieves at most 64 KiB from one immutable row in a short transaction. Public and private fields are projected separately; private pages recheck current membership, guest identity, epoch and case visibility. Revocation, retention or database failure after headers terminates the stream. Cancellation closes the producer; no database transaction spans network backpressure.

Terminal result header and case writes depend on migration 052 and the completion owner's canonical validated writer. Results without normalized headers fail closed. The privileged `backfillSubmissionBatch(run, limit)` selects at most 64 terminal submissions, locks each independently and records normalized rows atomically. Backfill reads old bytea in 64 KiB chunks and locks submission and execution rows; legacy case fields are located by byte range, validated and assembled in PostgreSQL. Variable-length legacy header fields and diagnostics are separately normalized and paged. New completion writers must keep only validated, bounded scalar/status metadata in the header. Conflicting 051 private sidecars are rebuilt only before a 052 header exists, under submission and execution locks and pre/post source and summary SHA-256 checks. The guarded deletion and replacement commit atomically; authoritative 052 rows cannot be repaired this way. Drain old result writers and judges before backfill and activation.

Validation on isolated PostgreSQL 55465 (`quorem_hono_result_stream_test`): Node result suite 23 passed; interview lifecycle suite 15 passed; workerd HTTP suite 6 passed, including >128 MiB total output, individual 16 MiB public and private cases, and a 16 MiB legacy diagnostic, with emitted chunks ≤64 KiB. Cancellation, lossless numeric/NUL values, restricted roles, revocation, retention and mid-stream outage were exercised. API typecheck and import boundaries passed. The incremental lexer identifies byte boundaries; PostgreSQL validates complete legacy case JSON and selected field types. Real 27 staging and promotion through interview reveal passed against PostgreSQL; repeat promotion preserved one receipt and left no staging, frames or chunks. Fresh schema catalog parity passed. Full admission-to-promotion composition and hosted validation remain outstanding.

CI run 41179200561 exposed an 8 s request-scoped lifetime reused for offline normalization: both 32 MiB legacy fixtures aborted after about 8.6 s. Operator callers must supply a separately bounded connection lifetime appropriate to the largest record and available temporary disk; the integration operator uses 120 s per submission. `backfillSubmissionBatch` uses a 30 s per-statement deadline and 1 s lock deadline; each submission commits separately. Timeout aborts and rolls back the submission, allowing an explicit retry. These bounds do not change HTTP connection or page deadlines and do not guarantee every legacy record completes within 120 s.

The locked public and private legacy sources are copied once into an uncompressed transaction-local PostgreSQL temporary table, dropped on commit or rollback. The reader fetches at most 64 KiB per page; raw source never enters application memory as a whole. This uses additional temporary disk proportional to source size. On local PostgreSQL, `EXPLAIN (ANALYZE, TIMING OFF)` of sequential 64 KiB slices of the same compressed 32 MiB fixture took 734.5 ms directly versus 6.8 ms from the spool (excluding the spool copy); the first 1 MiB took 1.17 ms versus 0.35 ms. These are local measurements, not production capacity guarantees.
