# Result streaming

The result routes capture a terminal header, authorized membership, sidecar completeness and PostgreSQL row versions before returning a pull-driven JSON stream. Each subsequent read retrieves at most 64 KiB from one immutable row in a short transaction. Public and private fields are projected separately; private pages recheck current membership, guest identity, epoch and case visibility. Revocation, retention or database failure after headers terminates the stream. Cancellation closes the producer; no database transaction spans network backpressure.

Terminal result header and case writes depend on migration 052 and the completion owner's canonical validated writer. Results without normalized headers fail closed. The privileged `backfillSubmissionBatch(run, limit)` selects at most 64 terminal submissions, locks each independently and records normalized rows atomically. Backfill reads old bytea in 64 KiB chunks and locks submission and execution rows; legacy case fields are located by byte range, validated and assembled in PostgreSQL. Variable-length legacy header fields and diagnostics are separately normalized and paged. New completion writers must keep only validated, bounded scalar/status metadata in the header. Conflicting 051 private sidecars are rebuilt only before a 052 header exists, under submission and execution locks and pre/post source and summary SHA-256 checks. The guarded deletion and replacement commit atomically; authoritative 052 rows cannot be repaired this way. Drain old result writers and judges before backfill and activation.
