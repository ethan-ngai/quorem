# Migration checksums

The shared product/auth migration owner hashes exact UTF-8 SQL bytes with SHA-256. Under each existing owner advisory lock and one transaction, it validates the entire applied contiguous prefix before running pending SQL; checksum drift and name-only history fail closed. New ledger rows include their checksum. Invalid UTF-8 fails rather than being silently converted. Fresh, prefix and repeat migration preserve the single existing ledger per owner. Auth's separate migrator now delegates to this owner.

`baselineLegacy(pool, owner, directory, evidence, authorizeAndAudit)` accepts only a fully name-only nonempty contiguous history and an exact manifest of original applied SQL hashes. Every current SQL file must match the independently verified manifest. It records operation ID, operator, reason and artifact provenance on the ledger rows in the same transaction after the required authorization/audit callback. The deployment owner must authenticate `VerifiedArtifact` from a successful production GitHub deployment and the Git objects at its exact commit and implement the product authorization/audit callback. This package does not authenticate GitHub claims; the structural port is a trust boundary, not proof by itself. There is deliberately no CLI or default authorization, and no automatic baseline.

Go's `apps/api/internal/adapters/postgres/store.go` still writes name-only product rows. Existing Go-generated and legacy auth ledgers therefore require an independently authenticated baseline, and Go must stop writing or adopt the checksum owner contract before mixed-reader activation. Tests that run Go migrations then call the TS owner need independently attributable fixture provenance; they are not silently baselined here. In particular, a successful deployment record must be verified before applying this to an existing environment.

Local validation on isolated PostgreSQL 17, port 55601: checksum/baseline/rollback/retry test 1/1 for both owners; fresh/prefix/repeat full schema parity 1/1; auth migration test 1/1; database and auth typechecks passed. No hosted deployment or GitHub provenance verification performed.
