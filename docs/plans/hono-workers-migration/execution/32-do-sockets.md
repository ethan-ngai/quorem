# 32: Durable Object browser sockets

`browserSocketObject` is a real hibernating Durable Object class factory; `postgresSocketAuthority` composes the existing identity, interview, match and submission owners. Runtime composition must export a class from the factory and route the supported `/v1/.../events` paths to the appropriate namespace. It must wire trusted outbox delivery to the object's `publish` RPC and choose a stable namespace identity for each `(stream, aggregate)`; if it shards an aggregate, it must fan notices out to all shards. These ingress and deployment bindings belong to runtime integration, not this packet. No production route or legacy relay changed.

The upgrade requires the exact allowed Origin and the `quorem` subprotocol; bearer material is never echoed. Authentication creates an opaque storage key after verification. The attachment holds only that key; the bounded private record holds verified issuer/subject/session/expiry and original strong-authority cap, or a scoped guest/invitation hash and expiry, plus the exact lease tuple. Wake rechecks live sessions, user binding, roles and scoped authorization. Anonymous invitations have no synthetic principal. The original credential expiry cannot be extended. Storage is capped at 1,024 records per object, records at 24 KiB, and alarms clean abandoned grants. This is a transport resource ceiling; PostgreSQL remains the per-user quota authority.

Interview and match windows share the same transactional `acquireSocketLease`/`renewSocketLease`/`releaseSocketLease` primitive: four windows per `(topic, subject)`, 30-second database-clock expiry, 10-second Worker renewal, and tuple-fenced release even after revocation. Membership and host checks are current in the owning transaction. Interview lease authorization locks authority rows without taking the document row lock. Membership notification routing uses the public participant UUID rather than the identity user ID.

Workers expose synchronous WebSocket sends without drain or buffered-byte visibility. Every outbound frame therefore uses `{receipt, payload}` with an unpredictable receipt; the common browser socket sends `{type:"receipt", id}` before handing the payload to the consumer. The shared session allows one unacknowledged frame, coalesces dirty notices, bounds queued responses, and closes a nonresponsive peer after five seconds. Receipts grant no domain authority. Full interview snapshots and result payloads remain on authorized bounded HTTP streams.
