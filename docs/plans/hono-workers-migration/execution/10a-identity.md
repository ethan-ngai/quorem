# 10a Managed identity and access (#353)

This slice supplies consumer-owned claims, principal, token verifier, session authority, binding and capabilities ports. The JOSE adapter accepts only Ed25519/EdDSA JWTs, validates issuer, audience, verified email, subject, session, expiry and issued-at bounds, and limits tokens and JWKS refresh size/count/time/rate. The internal HTTP session adapter distinguishes revoked credentials from authority failure. Every authentication performs a live session check; the strong-auth window uses that response. PostgreSQL identity and capability adapters use the database transaction scope and the existing user, binding, grant and quota tables. Provider subjects never link by email; roles come from product users. Odyssey has no entitlement gate here.

The `node-local` adapter requires a transport-provided loopback peer, an allowlisted fixture user and no bearer credential. It is not mounted in the Worker or public application. The credential parser rejects malformed Authorization before any fallback and rejects duplicate WebSocket bearer protocols. The code is not mounted in app.ts; integration must explicitly compose the verifier, private session authority and request-scoped DB connection. Guest principals, distributed budgets and all HTTP/socket route policy remain packet 10b or later work.

## Validation

With a disposable `postgres:17` container bound to `127.0.0.1:55437` and database `quorem_hono_identity_test`, `QUOREM_IDENTITY_TEST_DATABASE_URL=... vp -C apps/api exec vitest run --config src/adapters/identity/vitest.config.ts`: 6 tests pass, including signed token checks, key rotation, forged/expired/invalid claims, size and JWKS failure bounds, session revocation/outage, credential precedence, local loopback restriction, and Drizzle binding/role/grant/quota reads against disposable PostgreSQL 17. Tests use database `quorem_hono_identity_test` on port 55437 and apply existing product migrations; no development database is touched. `vp -C apps/api exec vitest run --config src/adapters/identity/vitest.workers.config.ts`: workerd Ed25519 fixture passed. `vp -C apps/api run typecheck` and `vp -C apps/api run check:boundaries` passed.

JOSE 6.2.12, Drizzle 0.45.4 and the workspace database package are declared by the API; the integration owner must update the root lockfile. This is local evidence only: no hosted JWKS/session authority, production token corpus, Hyperdrive identity connection, HTTP/socket integration, guest lifecycle or provider failover was tested. Unsafe integer JWT color revisions fail closed rather than losing precision. Native workerd testing covers cryptography, not PostgreSQL or network service bindings.
