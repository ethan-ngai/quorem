# 37m staged workload

First staged activation runs this baseline after sandbox proof and application acceptance. The operator reuses assembled credentials in memory and verifies signed runner/case state before and after: both must remain active at generation one with the exact release, bindings and namespace. Workload or control-check failure uses the existing queue detachment, control pause and runtime-role fence. The deployment receipt includes workload metrics and signed observations. Provider telemetry remains unverified. CI requires the disposable actor tests and one-match real HTTP/WebSocket/runner/verifier fixture, with zero skips.

`scripts/hono-stage-workload.mjs` uses 40 sequentially created canonical staged actors to create 20 two-person matches, opens 40 authenticated match sockets, acknowledges notices, starts 40 run admissions at 2/sec, and watches result sockets for change notices, fetching authorized snapshots on open, change and reconnect until accepted. Each participant's workspace comes from their authorized match snapshot. The driver records HTTP and command p50/p95, admission-to-result latency, errors, disconnects and reconnect attempts. HTTP and command latency include setup; admission pacing reports measured rate, span and maximum gap, and the full baseline fails below 1.9 admissions/sec. It closes sockets, leaves matches, and revokes actor sessions; the actor owner retains synthetic user rows. Failed cleanup fails the run. A 10-minute active budget aborts requests, socket work and actor creation, including catalog seeding. Cleanup has separate bounded connection, SQL and HTTP budgets; it can extend beyond the active budget.

Run only against the explicitly authorized isolated stage, with `HONO_STAGE_API_ORIGIN`, `HONO_STAGE_BROWSER_ORIGIN`, `ALLOWED_ORIGINS`, `QUOREM_STAGE_DATABASE_URL` and `BETTER_AUTH_SECRET` supplied by the stage operator. The existing actor owner validates the stage database and TLS. Invoke `node --experimental-strip-types scripts/hono-stage-workload.mjs`; do not print environment or fixture credentials. Successful fixture-only tests do not establish the baseline. A one-match/two-actor local integration passed against isolated Docker PostgreSQL on 55701, the real Node HTTP/WS runtime, runner and verifier; the test-only bridge supplies the browser fixture’s real actor tokens. No hosted run was performed here. The driver does not independently attest deployed release or namespace; validate those against the deployment receipt before running. Provider CPU/memory/cost, database connection/lock pressure, queue/outbox age, deadline lateness and lease failures need independent telemetry. Prolonged typing, reconnect storms, cold starts, queue outage and maximum suite/replay profiles remain separate rollout gates.
