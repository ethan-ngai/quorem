# 29a: immutable runner input foundation

Issue #402. Partial and unactivated: admission, private input transport, runner consumption, legacy backfill and cutover are not implemented. Existing full-fixture reads still apply.

Migration 053 adds content-addressed blobs verified by PostgreSQL SHA-256, concrete version and interview snapshot fixture indexes, and per-job input manifests. Fixture/job indexes are built unsealed, then sealed once; later reference changes fail. Job sealing checks its actual source digest, runtime/harness, concrete fixture, contiguous case count and sample count. Blob deletion is allowed only after all foreign-key references disappear; job/fixture retention controls referenced content. Source is a blob too, allowing paging instead of assuming legacy source size. Old writers and checkpoints must drain and existing fixtures require operator normalization before activation.

`indexRunnerFixture(tx, owner, raw)` is called within publication and admitted interview snapshot transactions. New bounded authoring payloads are parsed by the existing lossless codec, separated into metadata and stage/channel case blobs, inserted in batches and sealed. The 320-case PostgreSQL fixture verifies indexing and replay conflicts. Legacy normalization needs a separate streaming owner; passing a large legacy fixture through this function does not establish bounded Worker memory.

Admission integration uses `fixtureCaseRefs(tx, owner, channel, level)` to retrieve ordered fixed-size hashes, `storeCustomInput(tx, raw)` only after existing custom-case validation, then `bindJobInputs(tx, { jobId, owner, cases, caseCount, sampleCount, privateDetails, submitCasesAreSamples })` inside the existing transaction. The case selection and public/private channel assignment remain the admission policy owner's responsibility. Call after inserting the job and, for interviews, its `interview_execution` identity. Each `cases` entry is an ordered `{channel, hash}` obtained from the fixture index or validated custom input; samples use `sample`. The special interview sample fallback stores its cases only once, sets equal case/sample counts and `submitCasesAreSamples=true`. Sealing checks the resulting length and source/fixture/job binding; callers must still enforce correct selection and visibility.

Local checks: fresh disposable PostgreSQL migration and exact Drizzle catalog parity; 7 focused tests cover real publication and interview snapshot owners, 320 indexed cases, NUL preservation, conflicts, one-way sealing, source/fixture binding and cascading retention. These are not hosted capacity or a bounded-reader proof. The production migration is not deployed.

The private transport exposes a fixed-size manifest and 64 KiB pages for source, metadata and one case at a time. Each page rechecks the live job, attempt, sandbox scope, cancellation, runtime, limits and concrete source/suite identity. Node's private spool verifies a stable hash, size and channel across every page and checks the complete SHA-256 before making bytes readable to the execution owner. Temp files stay outside the sandbox and are removed on disposal or failure. Real workerd plus disposable PostgreSQL exercised 150 KiB metadata, page sizes and stale-attempt rejection; Node tests cover truncated, oversized, changed-hash and failed-lease reads. This transport is not yet consumed by the engine and does not alone prove streaming JSON comparison or per-case execution.
