# 35b Staged native deployment

Issue #412. This is a local infrastructure checkpoint, not an activation. No Terraform apply, cloud deploy or production traffic change was performed. `infra/terraform/hono-stage` owns a separate `*-hono-stage` Worker identity, execution queue, dead-letter queue, optional single-message/single-concurrency consumer and two Access applications. The existing live Worker and its v1–v4 Durable Object history remain untouched. The queue consumer defaults disabled; attach it only after deploying the staged Worker with its real queue handler. Its batch size is one, max wait one second, retry delay ten seconds, and concurrency one; one 210-second drain call fits inside Cloudflare's documented 15-minute queue invocation wall time. Cron recovery runs once per minute. Local plan-shaped tests do not prove hosted scheduling or throughput. [Cloudflare queue limits](https://developers.cloudflare.com/queues/platform/limits/)

Wrangler owns the separate Worker's source, cron, routes, three class migrations and bindings; Terraform owns Worker identity, queues, consumer and Access policy. This avoids two owners for one consumer. `scripts/hono-stage-config.mjs` accepts a public input JSON and `terraform output -json`, requiring the applied Worker/queue/Hyperdrive IDs, both Access application IDs and their exact protected hostnames. It binds `DB`, `EXECUTION_QUEUE`, `SOCKETS`, `DEADLINES`, `EXECUTION_RECOVERY` and optionally `PROFILE_BUCKET`; it explicitly disables workers.dev and preview URLs. Only stage-host `/v1/*`, `/api/auth/*`, `/health`, and `/internal/*` routes are generated. Apply the Access applications before publishing any route. The internal API path requires the configured service-token policy; the separate drain hostname has a separately scoped token and `/internal/drain` policy. Existing Access token IDs are inputs, never client secrets in Terraform state. [Cloudflare Access service tokens](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/deployment/device-enrollment/)

The provisioned Hyperdrive ID must point to a separate staged PostgreSQL database containing both schemas, with caching and connection budgets reviewed for writes. Required public inputs explicitly set `HTTP_MAX_REQUESTS`, `DEADLINE_SHARDS`, auth origin, allowed origins, verifier public key and drain URL; runtime validates optional `SOCKET_HEARTBEAT_MS` (default 15000 ms). `EXECUTION_DRAIN_ACCESS_MODE=cloudflare-access` is mandatory in the staged public configuration. Worker secrets include `MATCH_INVITE_KEY`, auth secrets, `RUNNER_PEERS`, `VERIFICATION_SOURCE_CREDENTIAL`, `VERIFICATION_SERVICE_CREDENTIAL`, `EXECUTION_DRAIN_SECRET`, and the separate `EXECUTION_DRAIN_ACCESS_CLIENT_ID` / `EXECUTION_DRAIN_ACCESS_CLIENT_SECRET`; provider-specific auth/mail/profile credentials are configured only when selected. `scripts/hono-stage-secrets.mjs` validates private credential separation in memory without printing or writing values. Inject verifier signing material only into the independent verifier, never into the API or sandbox.
