# 35b Staged native deployment

Issue #412. Terraform owns the isolated Worker identity, Hyperdrive, execution and dead-letter queues, optional bounded consumer, and staged profile bucket. Wrangler owns the API Worker code, bindings, Durable Object migrations, cron and Custom Domain. The consumer starts detached; attach it only after the deployed handler and hosted execution pass. Workers.dev and preview URLs remain disabled. Local Terraform mock tests do not establish hosted routing or throughput. [Cloudflare queue limits](https://developers.cloudflare.com/queues/platform/limits/)

`scripts/hono-stage-config.mjs` builds the API configuration from public inputs and Terraform outputs. It binds `DB`, `EXECUTION_QUEUE`, `SOCKETS`, `DEADLINES`, `EXECUTION_RECOVERY` and optionally `PROFILE_BUCKET`. The private API, drain, verifier, case and image endpoints use distinct purpose-scoped application bearer credentials. Case operations additionally require the pinned namespace, scope and signed proof. Use `EXECUTION_DRAIN_ACCESS_MODE=none` and `VERIFICATION_ACCESS_MODE=none`; no Cloudflare Access application or client pair is required. Unmatched routes remain rejected by the Worker.

The pinned provider marks private service Worker secret bindings and the Hyperdrive origin password sensitive, but not Terraform write-only. Remote state and saved plans can contain credentials and signing keys. Require encrypted state and transport, restricted access, and reviewed retention/deletion of plans, backups and state history. Rotation does not erase older copies. [Terraform sensitive data](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only)

The Hyperdrive origin must be the separate staged PostgreSQL database with both schemas, caching disabled and a reviewed connection budget. Runtime configuration includes explicit auth origin, allowed origins, `HTTP_MAX_REQUESTS`, `DEADLINE_SHARDS`, verifier public key and drain URL. `scripts/hono-stage-secrets.mjs` checks credential separation without printing values. Verifier signing material belongs only to the verifier; contestant containers receive no service credentials.

Local Terraform, Node and native workerd checks exercise configuration, private bearer denial and the runner/verifier entry points. Hosted Custom Domain routing, disabled alternate ingress, Hyperdrive origin identity, queue delivery, sandbox isolation and teardown, capacity and rollback remain separate activation gates. Do not infer hosted proof from mock plans or container health.
