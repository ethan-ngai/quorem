# 15: Durable dispatch

Issue #373. Migration 049 adds fenced, expiring claims to the existing four notice outboxes and a separate execution wake intent ledger. Admission must insert the execution intent in the job transaction. Claims are bounded; publishing occurs after the claim transaction and before compare-and-set acknowledgement. Stale or expired claims cannot acknowledge another claim. The repair operation rearms delivered intents for unfinished jobs without a live lease after one minute; a scheduler must invoke it and dispatch pending streams. One minute is a repair target, not a precise deadline.

The prewake helper awaits queue acceptance before invoking admission. Admission must enforce the supplied deadline and atomically insert its job and intent. Early wake consumption publishes a delayed continuation through the deadline before acknowledgement; pending work requires a continuation. A postcommit wake failure leaves the committed result and pending intent intact. Queue retry exhaustion requires scheduled repair and operational redrive; neither a timer nor waitUntil is sufficient.

Cloudflare native binding and REST pull queues and Node SQS use distinct adapters; Node PostgreSQL LISTEN is optional acceleration. No provider credentials are required for fixture tests. AWS uses its default credential chain. Trigger-owned notice rows remain the only notice source.

Validation: isolated PostgreSQL 55452/quorem_hono_dispatch_test exercises claim expiry, stale acknowledgement, publication failure, locked/uncommitted arrival, final-drain arrival, prewake failure and duplicate continuation. An actual execution job transaction covers early prewake, lost publish acknowledgement, duplicate retry, aged-intent repair and finished-job exclusion; LISTEN is exercised against PostgreSQL. Native workerd claims and acknowledges a PostgreSQL notice and publishes a delayed continuation. Provider protocol fixtures exercise Cloudflare binding/pull and SQS send/receive/ack/retry. API/database typechecks and boundary checks pass.

Integration gates: production admission, queue handler and scheduler are not mounted here. Existing deploy worker's notification parser discards phase/deadline, so it cannot consume this protocol safely; update it before activation. Enforce the admission deadline through transaction commit, wire atomic intent insertion and schedule the repair operation. The real-job test exercises the persistence primitives with a fixture admission and simulated queue failure; production admission and deployed queue/DLQ lifecycle remain unverified. Hosted queue delivery and recovery are not tested. Root must regenerate the dependency lock and any supply-chain policy entries for API-local AWS SQS and pg dependencies.
