## Findings

### P1 — Shared question types have multiple independent owners

`packages/questions/src/starter.ts:46-95` reimplements type recursion and TypeScript/OCaml mappings already in `apps/web/src/features/editor/questionTypes.ts:8-67`; only Java is shared via `packages/contracts/src/java-type.ts`. Example: preview collapses repeated optionals and TypeScript nullable nodes, while starter generates each optional recursively. Preview and generated sources therefore drift as type grammar grows; these are consumed by editor previews and API authoring/interview starter generation respectively. The same wrapper grammar is re-parsed by `packages/questions/src/signature.ts:6-15`, `value-codec.ts:32-57`, and several web consumers. Create a focused `@quorem/contracts` subpath (matching `java-type`) for shared recursion and mappings; avoid importing the questions barrel/Ajv into the web. Keep minimal separate display and source entry points to preserve parentheses and nullability; avoid a generic flags framework. Adopt incrementally, do not pull judge harness implementations across language boundaries. Validate nested optional/node/list/array, all languages, void, invalid types and preview/generated source equivalence where intended; retain explicit tests for intended differences. Risk: syntax and semantics for nullable node types, OCaml lists versus arrays, and existing display output.

### P2 — Staged starter generation parses its own generated text

`packages/questions/src/starter.ts:98-149` generates a complete class for every method, searches for the class header, slices it out, strips the trailing brace, and rewrites a zero-argument OCaml function by textual substitution. Class framing and method formatting are coupled by incidental string layout; changes to comments or framing can silently discard content. Generate method bodies directly once, compose classic or staged containers around them, and emit node notes once where appropriate. Consumers: problem authoring and custom interview questions. Preserve byte output if relied upon and validate Python/Java/TypeScript/OCaml classic and staged outputs including docs, node types, multiple methods and zero arguments, ideally with actual compilers. This slice can follow the formatter change or be isolated in the starter owner.

### P1 — Execution manifest rules duplicated and inconsistent at transport boundaries

`packages/execution/src/manifest-binding.ts:20-68` validates blobs, manifest and channel relationships; `apps/runner/src/queue/http.ts:161-211` repeats most of those rules independently, while `apps/runner/src/verification/source-http.ts:95-112` casts remote JSON and defers validation to `verifier.ts:73-78`. For example runner transport accepts a run manifest with fallback flags or samples that binding rejects later. These rules affect runner and independent verifier consistency and make a single contract change require multiple edits. Put explicit unknown-to-typed blob/manifest/ref decoding in `packages/execution`; use it at each HTTP boundary and from binding, retaining binding's ordinal, channel, job and attempt checks. Preserve operation-specific error classification and trust boundary validation; do not share credentials, execution, attestation or fence authority. Test malformed inputs, fallback/run combinations, count bounds, channels, replay, aborts, Node/workerd and verification paths. Changing rejection timing or error type is a material risk; pin observable behavior intentionally.

### P2 — Projection compatibility reimplemented in the editor

`packages/questions/src/constraints.ts:6-34` owns admissible projection/type combinations, yet `apps/web/src/features/editor/constraintValidation.ts:27-45` independently rebuilds the same list before evaluation, immediately after invoking canonical definition validation. Extract a small typed projection descriptor or projection evaluator in questions; keep editor presentation and `ConstraintViolation` messages local. This deletes an extra compatibility table rather than adding another policy. Validate all projection kinds, long arithmetic, node values, array aliases and invalid targets against both authoring and execution consumers. Coordinate with frontend ownership.

### P2 — Check old relay and migration probes for retirement

`apps/realtime-cloudflare/src/index.ts:1-5` still describes Go API ownership and contains a separate notice relay; repository-wide references found no runtime consumer of its `MATCH_RELAYS`/`RELAY_TOKEN` bindings. Current architecture assigns live sockets to API runtime and notice fanout to adapters. The package also supplies Wrangler to `.github/workflows/frontend.yaml:89`, so deleting the package outright would break deployment. `tools/migration-runtime` and `tools/migration-auth` are separate pinned spike workspaces referenced by historical migration docs. Confirm actual deployed routing, operator use and release workflow before removing relay/probes; move the CLI dependency to its real owner, update lockfile/workflows and remove only verified obsolete artifacts. No cloud state was inspected; this is a retirement candidate, not proof safe to delete.

## Sequencing and package assessment

Independent implementation slices: (1) question formatter plus starter composition, coordinating web consumers; (2) execution contract decoders, coordinating runner and API consumers; (3) constraint projection owner, coordinating editor changes. Keep the execution slice separate from sandbox or verification topology. Relay removal requires deployment evidence first. Existing AJV handles question schema; `ws` handles gateway sockets. No externally verified maintained package replacement was established that preserves lossless numbers, provider-neutral Workers/Node behavior, streaming bounds, fencing, or sandbox semantics; avoid speculative dependency additions.

## Disposition: PR #567

Implemented focused type rendering, direct staged composition, canonical projection admission reuse, and execution input decoders in PR #567. Source/display formatting intentionally retains distinct nullable and parenthesis output. Decoders reject inconsistent run/fallback manifests earlier and retain attempt, ordinal and channel binding checks. Tests cover Node, workerd, editor and runner transports; hosted isolation and database integration remain unverified. The old relay/probe retirement remains open pending deployed-state evidence. Broader type grammar duplication outside rendering remains a follow-up, not a claim of complete consolidation.
