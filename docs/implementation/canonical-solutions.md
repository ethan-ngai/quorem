# Canonical solutions

Ledger: [#510](https://github.com/ethan-ngai/quorem/issues/510).

Each coding question owns one Python `canonicalSolution` containing source, explanation and complexity. SQL questions use PostgreSQL. The same source serves as reference and default editorial; `solutions` contains only optional other-language editorials. `implementations` registers supported submission runtimes, starters and pinned runtime/harness revisions. No language-specific reference is required. Publication requires nonempty canonical code, its canonical runtime, unique supported editorial languages and valid bounded source. Incomplete drafts remain saveable. Custom interview questions retain their explicit expected-value flow: their private library snapshot may have no canonical code, and publishes no empty editorial. The custom-interview persistence option cannot publish a global problem.

`packages/questions` owns blank editorial defaults, full editorial projection and language fallback. Workspace and interview complexity availability use the same selector as editorial display: selected language when authored, otherwise Python/PostgreSQL. Render code using the selected editorial's language. Existing match spoiler checks, interview hint gates and staged editorial restrictions remain enforced. Public question metadata contains availability only; source stays behind the authorized editorial endpoint.

Admin edits the canonical source directly and optional editorials through the language picker. New coding drafts support all four submission runtimes independently of additional editorials. Existing restricted runtime definitions remain explicit and can enable another runtime without adding an editorial. Public preview projects the canonical editorial plus additions, excluding hidden cases. Seed questions contain their own complete editorial data; the separate editorial fixture installation path is removed.

Migration 073 retains existing published primary editorials; absent primary editorials are populated from the canonical runtime's reference. Drafts follow the same precedence. It removes per-language reference source, preserving only the exact SHA-256 reference leaf required by existing immutable judging identities. New runtime entries use an empty reference leaf. Frozen historical fixture/snapshot bytes remain immutable evidence; new execution fixtures omit reference code entirely. Replay reuses existing reference hashes instead of changing sealed language rows.

The migration preserves draft numeric lexemes and escaped NULs, increments revisions to fence stale saves, and clears obsolete import receipts. PostgreSQL JSON operators reject escaped NULs: conversion temporarily masks actual NUL escapes using a collision-free marker while retaining literal backslashes. Migration tests exercise populated sealed versions, distinct existing editorials, missing editorials and lossless draft data.

Deploy frontend/backend together through GitHub Actions; older backends reference the removed column. No production migration or deployment is implied by local validation. Fixed cases continue judging against stored expected outputs. Executing the canonical solution for custom expected outputs, compilation and caching are future work.
