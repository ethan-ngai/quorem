# Marketing homepage

Issues #16 and #30. Static Astro app in `apps/marketing`; React owns `/practice`, `/practice/{problem}` and `/match/{id}`.

- Lead with private competitive coding: Showdown, Free-for-all, shared challenges, invitations and host conduct policies. Editor capabilities are supporting functionality, not the marketing pitch.
- [Linear](https://linear.app/) informs fine linework for shared-problem competition diagrams; [Supabase](https://supabase.com/) informs asymmetric product surfaces; [Ramp](https://ramp.com/) and [Raycast](https://www.raycast.com/) inform spacing and product depth. The hero retains Code. Clash. Conquer. in upright condensed Barlow 800, with interactive swords; Geist section headings describe actual behavior. Showdown illustrates two independent contestants and submitted test counts; Free-for-all illustrates four parallel contestants racing to the first correct result. No opponent source is displayed. These static examples lead into layered challenge cards, a server-rendered lobby, shared read-only editor islands and a replayable submission sequence. Paired neutral/blue tokens and marketing-only shadow/radius tokens live in `DESIGN.md`.
- Tech Stacked, Factions, Codebase Clash and Odyssey are marketing-only conceptual previews, each visibly marked Coming soon. Diagrams show service replacement, competing parties, repository changes and object-model growth across rounds. No runtime game modes, availability dates or new scoring rules are implemented.
- Expanded Practice/Create match navigation collapses below 440px of available header width. Login stays disabled until #14; theme toggle lives in the footer.
- Below the match walkthrough, Social and Adaptive have Coming soon previews: an example leaderboard/head-to-head record and past results feeding a problem recommendation for practice or matches. Asymmetric feature cards contain layered, static product mockups with illustrative data; no social or recommendation runtime is added.
- Shared `@quorem/ui/theme.css`, Geist and `quorem.theme.v1`. System theme initially; explicit toggle persists across marketing/workspace.
- LobbyPreview server-renders the app's MatchSettings with an injected example catalog and its competitive stylesheet. No client hydration, API requests, real invite tokens or sessions. Disabled controls sit in an inert illustration.
- EditorPreview imports PythonEditor, TestCases and ResultContent, with the real workspace CSS scoped to the demos. The toolbar reuses the monochrome Python logo, Sample/Custom case tabs stay above the case browser, and Run/Submit stay at the bottom. HeroEditorPreview imports PythonEditor alone for a 440px Climbing Stairs typing scene, with variable timing, pauses, deletions and corrections; no cases or execution controls. A pause/resume/replay button controls the finite sequence. Both hero and test islands hydrate only when visible; source remains server-rendered without JavaScript. Editors use the shared readOnly preference and inert wrapper. A finite cursor/run sequence controls TestCases selection in its vertical left rail and independently scrollable right pane; fields, expected output and results come from the real components. It reveals pass/pass/fail for Two Sum, including duplicate-value output [0,0] versus [0,1]. No user source edits, persistence or judging requests.
- ProblemCards replaces the tilted placeholder stack with bounded stepped cards: Trapping Rain Water, Meeting Rooms II and Two Sum. Mode examples use Two Sum/Subsets; Adaptive uses Two Sum, Climbing Stairs and Number of Islands.
- SubmissionPreview replays received → judging → results → winner, with twenty per-player test cells. usePreviewSequence pauses offscreen/hidden and shows final states under reduced motion. Tests animate once for four seconds; submission replay takes 2.55 seconds. The existing headline and dot field are preserved.
- `vp -C apps/marketing run build` compiles the static page. Development builds Astro before services start; Vite serves it at the shared origin. Rebuild after marketing edits. `vp run build` assembles the homepage and React entry into one artifact.

Verified production at 1440×900 and 390×844 in light/dark: no page overflow or browser errors, readable mode diagrams, read-only editor hydration/theme synchronization, rendered lobby and submission replay. `vp check --fix` and `vp run build` passed.
